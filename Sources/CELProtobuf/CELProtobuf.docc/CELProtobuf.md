# ``CELProtobuf``

Protobuf messages, enums, extensions and well-known types as CEL values.

## Overview

CEL was designed around protobuf: expressions select message fields (`msg.items[0].price`), test
their presence (`has(msg.discount)`), construct messages (`pkg.Order{id: 1}`) and treat the
well-known types as CEL values, so a `google.protobuf.Timestamp` field is a `timestamp` and a
`google.protobuf.Struct` a `map(string, dyn)`. This module gives the CEL runtime that view of the
messages generated by [swift-protobuf](https://github.com/apple/swift-protobuf), with cel-go's
semantics for defaults, presence, wrappers, `Any` and equality.

Generated code describes the messages: the `protoc-gen-cel-swift` plugin, run next to
`protoc-gen-swift`, writes one ``ProtobufFile`` constant per `.proto` file. ``ProtobufTypes``
collects those files and is both the type provider an `Environment` resolves message types with
and the adapter that turns messages into CEL values:

```swift
import CEL
import CELProtobuf

let protos = ProtobufTypes(files: [Google_Expr_Proto3_Test_TestAllTypes_CELFile])
let env = try Environment(
  .typeProvider(protos),
  .variable("msg", .objectType("google.expr.proto3.test.TestAllTypes"))
)
var message = Google_Expr_Proto3_Test_TestAllTypes()
message.singleInt64 = 7
let program = try env.program(env.compile("msg.single_int64 > 5"))
print(try program.evaluate(["msg": protos.value(of: message)]).value)   // true
```

<doc:UsingProtobufMessages> covers generating the files, constructing messages in expressions and
converting results back.

There are no dynamic messages built from descriptor sets at runtime: every message type CEL sees is
generated Swift code.
